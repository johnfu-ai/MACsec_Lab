## 4.3 Key Server 选举

一把 CAK 对应一个 CA，而每个 CA 里只能有一个成员负责生成和分发 SAK——这就是 Key Server。没有唯一的分发者，两端可能同时发出各自的 SAK，造成"双钥匙冲突"；有了选举，分发权唯一，秩序自洽。

KS 是 CA 里**唯一**生成和分发 SAK 的成员（一把 CAK 对应一个当选者）。每个成员在 Basic 参数集里宣告：

- **Key Server 标志位**（自己认为能不能当）+ **优先级**（1 字节）
- 选举规则：**优先级数值最小者当选；平局时 SCI 数值小者当选**。数值越小越"想当"。

### 4.3.1 三条故事线里的选举

实验室的抓包把选举规则演了三遍：

- PSK 线 A（prio 16）胜 B（32），见 [`mka-handshake.pcap`](../captures/mka-handshake.pcap) 帧 1-2 的 `Key Server Priority` 字段；
- EAP 线 Authenticator（prio 0）固定胜 Supplicant（255），见 [`mka-after-eap.pcap`](../captures/mka-after-eap.pcap)；
- 多成员 CA 里 KS 同样只有一个（[`mka-multi-peer.pcap`](../captures/mka-multi-peer.pcap)），SAK 分发一次全体可用。

值得体会的设计是：选举不产生额外的报文，它就藏在每条 MKPDU 的 Basic 参数集里——宣告本身就是投票。
