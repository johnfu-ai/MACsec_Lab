## 3.5 丢弃是静默的：计数器与排障

静默丢弃是安全上的正确选择，却是运维上的噩梦——对端不会告诉你它丢了你的帧。为此，标准定义了一组每 SA/每 SC 计数器，它们是判断"MACsec 是否健康"的主要依据，也是把 3.3 节五道关的内部行为"翻译"给人看的唯一窗口。

### 3.5.1 计数器一览

这组计数器与 [11.5 运维清单](../11_deployments/11.5_operations.md)的监控项、[10.5 排障指南](../10_lab/10.5_troubleshooting.md)的排查矩阵一一对应：

| 计数器 | 含义 | 常见原因 |
|---|---|---|
| `InPktsUnknownSCI` | SCI 不认识 | 对端先发数据后完成 MKA；SCID 配错 |
| `InPktsNoSA` / `InPktsSANotInUse` | AN 没有启用中的 SA | 换钥过渡不同步 |
| `InPktsBadTag` | ICV 校验失败 | **密钥不一致 / 线路误码 / 被篡改** |
| `InPktsLate` / `InPktsNotUsingSA` | 重放窗口/Delay Protect 丢弃 | 真乱序超窗、路径时延 > MKA 周期 |
| `InPktsUntagged` | untagged 帧按策略丢弃 | 对端没开 MACsec、策略是 strict |

### 3.5.2 排查口诀

`BadTag` 涨 → 查密钥（CAK/CKN/SAK）；`UnknownSCI` 涨 → 查 MKA 会话与 SCI 配置；`Late` 涨 → 查网络时延与 delay protect 配置。

### 3.5.3 与本仓库的对应

- 发送路径的每一步 = [`macsec_lab/macsec.py`](../macsec_lab/macsec.py) 的 `protect_frame()`；接收路径 = `parse_frame()` + `ReplayWindow` + `XpnPnTracker`。
- 五道关里能在**抓包上直接看到**的：SA/AN（SecTAG）、PN、ICV；SCI 查找与策略丢弃是设备内部行为，抓包只能看到"帧还在路上"。
- 想亲眼看丢弃：`make test` 里有 tamper（ICV 关）、replay（窗口关）、delay floor（LPN 关）三类用例。
