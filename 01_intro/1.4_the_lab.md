## 1.4 本书与实验室：可验证的知识库

本书不是纯文字读物：仓库本身就是一个可运行的实验室，书中的每一个关键论断都能落到某个 pcap 或某条测试断言上。本节介绍实验室的构成、它为什么不用内核 MACsec，以及怎么用它验证书里的知识。

### 1.4.1 实验室构成

三件套支撑起"可验证"三个字：

- **15 个参考抓包**（`captures/*.pcap`）：Wireshark 可直接打开，覆盖 PSK 握手、EAP 之后、换钥、重放窗口、Delay Protect、XPN、多成员 CA 等全部故事线；
- **35 项测试**（`make test`）：与 IEEE 公开 GCM 测试向量**逐字节比对 ICV**，外加往返加解密、SAK 解包等断言；
- **15 份字段级报告**（`captures/decoded/*.md`）：本仓库自己的解析器产出，不依赖 Wireshark 密钥表，每份都是总览表 + 逐字段偏移表 + 十六进制（导读见[附录 D](../14_appendix/D_reports.md)）。

### 1.4.2 为什么不用内核 MACsec

写作环境是 WSL2，内核报告 `# CONFIG_MACSEC is not set`，因此数据面抓包不是 `ip macsec` 内核卸载出来的，而是按 802.1AE 组帧、密码学与 [IEEE GCM 测试向量](https://ieee802.org/1/files/public/docs2011/bn-randall-test-vectors-0511-v1.pdf) 对齐的构造帧。MKA 则走真实 EAPOL（EtherType `0x888E`，Packet Type 5），Wireshark 的 `mka` 解析器可以直接展开。真实内核部署路径（wpa_supplicant + `ip macsec`）在[第十一章](../11_deployments/README.md)单独讨论；实验室规格的完整定义见[附录 C](../14_appendix/C_spec.md)。

### 1.4.3 代码地图

| 目录 | 内容 |
|---|---|
| `macsec_lab/` | 组包 / 解包 / 密钥派生 / 接收端模型（crypto、macsec、mka、scenario） |
| `tests/` | 35 项断言，IEEE 向量必须通过 |
| `captures/` | 15 个参考 pcap + `keys.json` + `decoded/` 字段级报告 |
| `scripts/` | generate / verify / live netns 脚本 |
| `examples/c/` | SecTAG 比特布局（教学子集） |

### 1.4.4 怎么用好它

最快的用法只有一行：在 `make test` 里改掉任何一个常量（密钥/PN/AAD），看哪条断言先挂——**挂掉的顺序就是概念重要性的顺序**。改错了密钥，ICV 比对立刻红；改错了 AAD 里的 `0x88E5`，下一层断言才红。完整的操作手册（生成、Wireshark 联动、live 实验、排障）在[第十章](../10_lab/README.md)。
