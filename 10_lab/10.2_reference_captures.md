## 10.2 十五个参考抓包导读

实验室的 15 个参考 pcap 各讲一个故事：握手、重加密、重放、延迟保护、XPN、多成员……每份抓包都和正文的某一节互为证据。这一节给出"抓包 ↔ 章节"的对照表，帮你按需取用。

### 10.2.1 抓包对照表

| 文件 | 用途 |
| --- | --- |
| [`captures/mka-handshake.pcap`](../captures/mka-handshake.pcap) | 6 帧 MKA（PSK CAK）：hello → 选 KS → 分发 SAK → 双方 SAK Use |
| [`captures/mka-after-eap.pcap`](../captures/mka-after-eap.pcap) | EAP-Success 之后：Authenticator 为 KS，CAK 从 MSK 派生（[5.5 节](../05_wire_format/5.5_psk_vs_eap.md)） |
| [`captures/mka-rekey.pcap`](../captures/mka-rekey.pcap) | SAK 重加密：AN=0 → AN=1，双 SA 并存 → 旧钥退役（[6.2 节](../06_lifecycle/6.2_rekey_on_wire.md)） |

### 10.2.2 不用 Wireshark 的手工解码

本仓库自带解析器，不依赖 Wireshark 的密钥表，就能为每份抓包生成"总览表 + 逐字段偏移表 + 十六进制"三件套报告：

```bash
PYTHONPATH=. python3 -m macsec_lab analyze
# → captures/decoded/*.md  (ICV checked, SAK unwrapped, inner IPv4 shown)
```

报告由 `make generate` 自动生成，字段级导读见[附录 D](../14_appendix/D_reports.md)。它与 Wireshark 的分工是：Wireshark 负责交互式浏览，本仓库解析器负责"ICV 是否有效、SAK 解封结果、解密后的内层 IPv4"这类需要密钥才能回答的问题——两条路径对同一份 pcap 的解读应当完全一致，这本身就是一次交叉验证。
