## 10.5 排障指南

实验室常见故障一共六种，从"测试挂了"到"live 实验抓不到包"。这一节按症状给出原因与处置，绝大多数问题都能在两条命令内定位。

### 10.5.1 `make test` 在 IEEE 向量上失败

`cryptography` 库的 AES-GCM 必须与 NIST SP 800-38D 完全一致。先执行：

```bash
python3 -m pip install -r requirements.txt
```

同时**不要**改动 `keys.py` 里的 IEEE 常量（TCI/SL/PN/SCI）——它们是官方向量的组成部分，改一个字节，逐字节比对必然失败。

### 10.5.2 tshark 显示 MACsec `[UNVERIFIED]`

这是**预期行为**：Wireshark 还没有拿到 SAK。两条路任选：

- Preferences → Protocols → MKA → 填入 `captures/keys.json` 的 CKN + CAK，Wireshark 即可从 MKA 抓包中解封 SAK（见 [10.3 节](10.3_wireshark.md)）；
- 或者直接信任 `captures/decoded/*.md` —— 本仓库解析器已经给出 `ICV valid = True` 的结论。

### 10.5.3 tshark 不显示 `mka`

Wireshark/tshark 版本要新到包含 `packet-mka.c` 解析器（实验室在 tshark 4.6 上验证过）。旧版本下过滤器 `eapol.type == 5` 仍然有效，可以把 MKA 按 EAPOL 过滤出来。

### 10.5.4 `sudo make lab` 抓不到 MKA

Linux 网桥默认丢弃 PAE 组播目的地址 `01:80:c2:00:00:03`。除非执行：

```bash
echo 8 | sudo tee /sys/class/net/br-macsec/bridge/group_fwd_mask
```

实验室脚本已经自动写这一位；若你手工重建过网桥，需要重新设置（详见 [10.4 节](10.4_live.md)）。

### 10.5.5 主机没有 `CONFIG_MACSEC`

在这台 WSL2 内核上是**正常现象**。不要指望 `ip link add type macsec` 能创建可用的 SecY——参考抓包的生成不依赖该模块，纯 Python 组包即可复现全部故事线。

### 10.5.6 加密抓包里看不到内层 IPv4

加密模式下内层本来就不可见。两个办法：

- 改看 [`captures/macsec-lab-integrity-only.pcap`](../captures/macsec-lab-integrity-only.pcap)（`E=0 C=0`，内层明文可见）；
- 或运行 `PYTHONPATH=. python3 -m macsec_lab analyze`，解析器会用实验室 SAK 解密并展示内层 IPv4。
