## 11.3 网卡卸载

软件 SecY 的吞吐天花板在 CPU；线速 MACsec 靠的是网卡（NIC）inline 卸载——加密在数据通路上的专用硬件里完成，对 CPU 几乎零占用。

### 11.3.1 有 MACsec 能力的硬件

| 硬件 | MACsec 能力 |
|---|---|
| Intel E810 | inline MACsec（ice 驱动），四套件 |
| NVIDIA/Mellanox ConnectX-6 Dx / ConnectX-7 | inline MACsec + IPsec，25G–400G |
| 交换 ASIC（Broadcom Tomahawk 系列等） | 线速 MACsec，DC/运营商平台常用 |

### 11.3.2 怎么判断一台机器有没有卸载

```bash
ethtool -k <iface> | grep macsec    # 找 macsec-hw-offload 类条目
```

有硬件卸载时，[11.1 节](11.1_linux.md)的内核路径会把 GCM 运算下沉到网卡，`ip macsec show` 的统计仍然可见——控制面归属内核与 wpa_supplicant，数据面归属 NIC，这正是 SecY 模型（[第三章](../03_secy/README.md)）在工程上的体现。

一个值得注意的观测细节：卸载路径下，**镜像口抓到的总是密文**——解密发生在网卡内部，任何中间捕获点都看不到明文。这既是安全特性，也是取证时的注意点（见 [9.6 节](../09_attacks/9.6_leaks_summary.md)的捕获点讨论）。
