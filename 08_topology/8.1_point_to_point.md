## 8.1 点对点：抓包模拟的逻辑拓扑

读抓包之前，先要知道"谁是谁"。本仓库绝大多数故事线发生在一个最小的拓扑上：两台直连的设备，各自一块网卡，预先配好同一套 PSK CAK/CKN。这个拓扑小到能把每一帧都讲清楚，又完整覆盖了"选举—分发—加密"的全部环节。

### 8.1.1 逻辑拓扑图

```
  node-a (Key Server)                 node-b
  MAC 02:00:00:00:00:0a               MAC 02:00:00:00:00:0b
  SCI  02:00:00:00:00:0a:00:01        SCI  02:00:00:00:00:0b:00:01
  KS priority 16                      KS priority 32
  10.10.0.10/24                       10.10.0.20/24
           \                             /
            \   PAE group 01:80:c2:00:00:03
             \         (MKA)            /
              +---------- LAN ----------+
                       MACsec 0x88E5
```

图 8-1：点对点逻辑拓扑

### 8.1.2 MAC、SCI 与 KS 优先级

三个标识符各就各位：**MAC** 是网卡地址；**SCI** = MAC‖PortID（这里的 `:00:01` 就是 PortID 1），是数据面每个发送方向的身份证；**KS priority** 是 Key Server 选举的筹码——数值越小越优先，所以 node-a（16）会赢过 node-b（32）。选举规则的完整版见 [4.3 Key Server 选举](../04_mka/4.3_ks_election.md)。

### 8.1.3 一条完整故事线

两端持有相同的 CAK/CKN（PSK）。MKA 开始后：A 赢得 Key Server（优先级更小）；A 用 KEK 封装 SAK 发出 Distributed SAK；之后双向的数据帧都用这把 SAK 保护。这条故事线的六帧握手见 [5.3 控制面六帧](../05_wire_format/5.3_control_plane_frames.md)，完整版（含加密数据面共 13 帧）在 [`captures/session-full.pcap`](../captures/session-full.pcap) 与字段报告 [`captures/decoded/06-session-full.md`](../captures/decoded/06-session-full.md)。
